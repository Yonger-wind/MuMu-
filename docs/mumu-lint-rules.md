# 暮幕内容校验器 · 规则码表

`tools/lint.js` 是**离线**校验器：只读剧本原文，不参与游戏运行，零依赖、无构建步骤。
每条问题都带「行号 + 规则码 + 原因 + 修法提示」，文案与工具输出逐字一致。

## 用法

```bash
node tools/lint.js 剧本.txt           # 校验单个 .txt / .md 剧本
node tools/lint.js --builtin          # 校验内置 15 章
node tools/lint.js --builtin --json   # 机器可读输出
node tools/lint.js 剧本.txt --strict  # 把警告也算失败
```

`--json` 输出 `{ ok, files, issues, summary }`，stdout 是纯 JSON，`ok` 与退出码同义；
诊断信息一律走 stderr。可用参数只有 `--builtin` / `--json` / `--strict`，其余 `--xxx` 视为用法错误。

## 退出码

| 退出码 | 含义 |
| --- | --- |
| `0` | 通过：没有 error；`--strict` 下也没有 warning |
| `1` | 有 error；加 `--strict` 时 warning 也算 |
| `2` | 用法错误：未知参数、没有目标、文件不存在、目标不是普通文件（目录 / 不可读）、格式不支持 |

## 五条口径（务必先读）

1. **`E105` 覆盖两类写法**：选项行 `> 文本` 缺落点；跳转行只有一个 `->` 缺目标。
   两类都会被解析器**整行降级成旁白** —— 选项凭空消失、跳转不再发生。
2. **断链（`E103`）时该文件不报 `E106`**：解析器会直接拒绝该剧本，「某段玩家永远走不到」
   是误导。一处断链会让整个文件失去不可达检测 —— 这是校验器自己的判断，不是解析器的语义。
3. **`E100` 是解析器交叉验证的兜底**：扫描器没覆盖到的致命错误（例如「没有读取到任何台词或旁白」）
   以解析器原文报出；同一行已有更具体的 error 时不重复报。
4. **`--strict` 把 warning 也算失败**；默认只看 error。
5. **只支持 `.txt` / `.md`**：`.json` 剧本（或首字符为 `{` 的文件）会被拒绝并退出码 `2`；
   目录 / 不可读路径同样退出码 `2`。

## 回归基线

`node tools/lint.js --builtin` 必须输出「通过：内置 15 章 未发现问题。」。
这是回归基线：新增规则若误伤内置 15 章，应当改规则，而不是改基线。
