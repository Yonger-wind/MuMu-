# 首屏性能基线（P0-5）

**采集方式**：`PORT=5199 node serve.js` + `node tools/perf-baseline.cjs --runs=3 --stage`
**采集日期**：2026-11-24（基线列 = P0-5 立绘/场景图懒加载前；懒加载后列 = 同一台机器、同一 Edge 版本，各自冷缓存导航复跑；每次调用新起 Edge，同一调用的 3 轮共用该进程）
**环境**：headless Edge（本机），1440×900，DPR 1，`Network.setCacheDisabled(true)` 冷加载；本地服务器无 gzip、无缓存头。每项 3 次取中位数。
**指标口径**：首屏可交互 = 导航开始 → `load` 完成 + 字体就绪 + 连续两帧 rAF，由 `Page.addScriptToEvaluateOnNewDocument` 注入的脚本在页面内用 `performance.now()` 写入 `window.__readyAt`（不含 CDP 轮询与往返开销）；体积 = `transferSize` 按类型汇总；请求数 = 子资源 + 1（HTML 文档本身）；FPS = 首页夕阳 / 舞台采样 3 秒；舞台 FPS 在入场遮罩未关闭的舞台页采样（前后同条件，只作同机对比）。

| 指标 | 基线（P0-5 改动前） | 懒加载后 | 变化 |
|---|---|---|---|
| 首屏可交互（ms） | 383 | 247 | −136（−36%） |
| load（ms） | 328 | 140 | −188（−57%） |
| 首屏请求数 | 53 | 21 | −32（−60%） |
| 首屏图片请求数 | 32 | 0 | −32（图片请求全部推迟到交互后） |
| 首屏总字节（KB） | 5806 | 1280 | −4526（−78%） |
| JS 字节（KB） | 1256 | 1259 | +3（+0.2%，懒加载调度代码） |
| 图片字节（KB） | 4529 | 0 | −4529（−100%） |
| 首页 FPS | 47.1 | 47.4 | +0.3（持平） |
| 舞台 FPS | 58.0 | 58.7 | +0.7（持平） |

**结论**：

1. 首屏少 32 个图片请求、约 4.5 MB —— 二十八张立绘改为首页空闲后分批加载，四张场景大图改为首次交互（打开剧本库 / 进入舞台）后加载，首屏只剩 HTML / CSS / JS。
2. 首屏可交互 383 → 247 ms（−36%），load 328 → 140 ms；`load` 与 DCL 同步，说明首屏不再等待任何图片解码。
3. 首页 47.4 FPS、舞台 58.7 FPS，中位数差 < 2%（首页两列合计单轮 42.8–48.7：基线列低至 42.8，懒加载后为 46.4–47.7，属机器噪音）；立绘分批预加载没有引入掉帧，舞台 P95 帧间隔仍是 16.8 ms。首轮 ready 392 ms 含冷启动热身，取的是 3 次中位数。
4. 首次进入舞台后会自然补齐 32 个图片请求（回归实测全部 200），画面与改动前一致；本地/回归环境下场景首次出现时大图已就位；慢网下先走既有程序化降级，大图到达后自动重绘，不需要另做预热点。

**补充数字**：DCL 140 ms · TTFB 7 → 10 ms · CSS 21 KB · 首页 P95 帧间隔 33.4 ms（>20 ms 共 39 → 38 帧，3 次中位数）· 舞台 P95 帧间隔 16.8 ms（>20 ms 共 6 → 4 帧）。
**已知限制**：四张场景大图在本次页面会话内只请求一次（sceneImagesRequested 置真后不再重试）；任一张瞬时失败，本次会话保持程序化降级画面，刷新页面后重新请求。立绘有 5 s / 2 次的有界自动重试，场景图没有（与懒加载前的单次加载行为一致）。
**已知噪音**：唯一控制台/网络异常是 `http 404 /favicon.ico`（浏览器自动请求，`serve.js` 无此文件，与 P0-5 无关，每轮 1 条，报错按 `run N:` 标注轮次）；该请求也计入「首屏请求数」与 `ico 0 KB` 分类。headless Edge + `--disable-gpu` 下的 FPS 只作同机前后对比用。

**如何复跑**：`PORT=5199 node serve.js &`，然后 `node tools/perf-baseline.cjs --runs=3 --stage --out=.tmp-perf/after.json`（上表「懒加载后」列即该文件的中位数）。数字随机器与 Edge 版本变化，对比只认同机同版本 Edge 的多次冷缓存导航中位数（每次调用新起 Edge）：首屏可交互允许 ±5% 波动、FPS 允许 ±10%；采集器会先校验 9334 端口归属（占用即报错退出）、校验导航后页面为 `http:` 且含 `#btn-start`，任一轮异常都不会产出「看似正常」的 0 值。
**不做项**：`scene.js` 按场景拆分/分片未在 P0-5 内执行（改动面大、收益低于图片懒加载），延后到后续性能切片；本表只覆盖首屏与舞台帧率两项。

# 2026-11-26 复测（收尾阶段，含 `lazy-scene` 方法变更）

**采集方式 / 环境**：与第一轮完全一致（`PORT=5199 node serve.js` + `node tools/perf-baseline.cjs --runs=3 --stage`，headless Edge 1440×900、DPR 1、冷缓存、无 gzip、无缓存头，3 次取中位数）。同机同版本，可与 11-24 直接前后对比。

## 方法变更：`scene.js` 移出首屏导入图

P0-5 当时把「`scene.js` 按场景拆分」列为不做项，本轮用更轻的办法拿到了大部分收益：新增 `scripts/lazy-scene.js` —— 一个与 `createSceneRenderer` **同接口**的懒加载代理。`scripts/main.js` 只静态导入这个约 4 KB 的代理，真正的 `scene.js`（738 KB）与它静态依赖的 `prop.js`（213 KB）在首次需要绘制场景时才 `import()`。

代理对外行为不变：`start/paint/resize/preloadImages/onChange/state/ready/whenReady` 全部照原样转发；ready 之前调用 `start()` 会缓存最后一次参数并在模块落地后重放，因此「进舞台 → 场景出现」的时序与拆分前一致；模块加载失败被吞成 `onFail` 回调（首页 toast「场景加载失败，请刷新页面重试。」），不产生未处理的 Promise rejection，也不会拖垮首屏。`main.js` 里两处 `sceneRenderer.preloadImages()` 预热点保留原位置（单测断言 ≥2 处），首屏仍不做图片请求。

## 结论

1. **退化被补回来了，且体积腰斩**。11-26 修复前 ready 357 ms / 1560 KB 相对 11-24 基线明显退化，根因是首屏导入图随 P2~P5 各轮膨胀：`scene.js` + `prop.js` 合计 951 KB 被静态导入，占首屏 JS 的 61%。拆出后 ready 357 → 272 ms，首屏字节 1560 → 643 KB（−58.5%），比 11-24 基线还低 49.8%。
2. **ready 仍比 11-24 高 10.1%，超出 ±5% 容差**，原因不在 JS：CSS 从 21 KB 涨到 107 KB（图鉴 / 自定义卡片 / 环形剧目 / 开场动画 / 滑行药丸 / 横屏适配的新增样式），首屏请求数从 21 涨到 34（ES Module 图就是打包图，每多一个模块多一次往返）。本地无 gzip 时这 86 KB 原文下载 + 34 次往返是纯成本，`lazy-scene` 无法覆盖。托管侧（Qoder Sites 走 CDN + 压缩）实际首屏字节会远低于本表。
3. **帧率**：首页 44.7 FPS 相对基线 −5.7%，在 ±10% 容差内；舞台 52.0 FPS 相对基线 −11.4%，略超容差。同日纵向看是单调改善的（47.7 → 48.7 → 52.0，>20 ms 帧 31 → 27 → 19），差额来自 11-24 之后新增的开场动画（WebGL2）、滑行药丸弹簧、全息扫光等动效，属功能成本而非本次改动引入的回退。headless `--disable-gpu` 下 FPS 只作同机前后对比。
4. **测量噪音**：`final.json` 三轮 ready 为 537 / 272 / 256 ms，首轮含 Edge 进程冷启动（DCL 434 ms），取中位数已排除；这与 11-24 记录的首轮 392 ms 是同一现象。
5. **风险**：`lazy-scene` 让「首次进舞台」多一次模块加载。本地实测该 import 在入场遮罩期间完成，观感无变化；慢网下首帧场景可能短暂为空 —— 由 `onFail` toast 兜底，不阻塞对话文本播放。

## 评估后未做的项

| 候选 | 首屏字节 | 否决理由 |
|---|---|---|
| `scripts/builtin.js` 懒加载 | 172 KB | 首页剧目选择、章节抽屉、自动存档校验都要它；改懒加载要在多处补 await，收益（约 −60 ms）换不确定性不值 |
| `package.js` + `zip.js` 懒加载 | 33.5 KB | 只在导入/导出弹窗用到，但入口只有一个且已在弹窗回调里，改动面小收益也小，留作后续 |
| 图鉴链（`gallery*.js` + `custom-cards*.js`） | ≈95 KB | 首页右上角功能组直接指向图鉴，懒加载会让首次点击出现空窗 |

下一步若要压回 ±5% 以内，方向是 CSS 分片（把图鉴/自定义卡片/开场动画的样式随模块注入）或托管侧 gzip + 合并模块，而不是继续动业务代码。
