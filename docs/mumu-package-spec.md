# 暮幕作品包 `.mumu` · 作者手册

面向作者与二次创作者：一部作品怎么被打包带走，又怎么在另一台浏览器里原样演出来。

本手册描述的每一个字段、限额与报错文案，都以 `scripts/package.js`、`scripts/zip.js`、
`scripts/serialize.js`、`scripts/parser.js` 的实现为准。

---

## 1. 作品包是什么

- 一个 `.mumu` 文件就是一个**标准 ZIP 容器**（MIME `application/zip`），里面装着
  `manifest.json` + 剧本文本 + 可选封面。
- 导出与导入**全部在浏览器内完成**：不上传服务器、不要账号、断网也能用。
- 两种粒度：
  - **单章包**（`kind: "work"`）：一章一部作品，导入后是独立卡片。
  - **整本包**（`kind: "series"`）：一整部曲目，导入后是一张曲目卡，章内再选章节。
- 包里保存的是**剧本文本**：从暮幕导出的包装的是原始文本，导入后播放结果与导出前逐句一致
  （个别没有原文的老剧本走重建文本，边界见 §10.2）。
- 作品本身仍然只存在浏览器本地（存储键 `mumu.scripts.v1`）；`.mumu` 只是把这份数据
  搬家的方式。

---

## 2. 快速上手

1. 首页「选择剧本」→ 找到要带走的那部作品。
2. 导出：
   - 独立卡 → 「导出 .mumu」（单章包）；
   - 曲目卡 → 「导出整本」（整本包）；
   - 章节列表里的任意一行 → 「导出」（该章的单章包）。
3. 把 `.mumu` 传给另一台设备（网盘、邮件、U 盘都行，它就是个 ZIP）。
4. 在另一台浏览器里打开暮幕 → 首页「导入」→ 把 `.mumu` 拖进去。
5. 导入的作品出现在「选择剧本」里，卡片左上角带「已导入」徽标。

导出是**只读操作**，不改动本地任何数据。

## 3. 包内结构

### 3.1 单章包

```
example.mumu
├── manifest.json      必需，包清单
├── script.txt         必需，剧本文本（暮幕 DSL）
├── assets/cover.jpg   可选，封面图
├── README.md          可选，模板生成的说明
└── LICENSE.txt        可选，许可证全文
```

### 3.2 整本（曲目）包

```
example-series.mumu
├── manifest.json      必需
├── chapters/01.txt    必需，第 1 章原文
├── chapters/02.txt    必需，第 2 章原文
├── chapters/03.txt    第 3 章原文（按章序依次编号）
├── assets/cover.jpg   可选，曲目封面
├── README.md          可选
└── LICENSE.txt        可选
```

两种布局**共用同一套 manifest**：单章包就是 `works` 长度为 1 的包，导入端只需一套解析逻辑。
封面扩展名与 `assets[].type` 的实际 MIME 一一对应：`image/jpeg` → `.jpg`、
`image/png` → `.png`、`image/webp` → `.webp`。

> 内置曲目导出时**不带封面**：内置剧本没有封面图数据；导入过的包再导出，封面会跟着走。

## 4. manifest 字段表

字段表与 `scripts/package.js` 的 `makeManifest()` 完全一致。
包里的 `manifest.json` 以两空格缩进写出，作者可以解开 ZIP 手工编辑后再压回去。

### 4.1 顶层字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `format` | string | 固定为 `mumu-package`。不是这个值就不是暮幕作品包。 |
| `formatVersion` | number | 容器格式版本，当前为 `1`。 |
| `schemaVersion` | number | 内容 schema 版本，当前为 `2`。 |
| `kind` | string | `work` = 单章；`series` = 整本曲目。 |
| `id` | string | 包 id。`kind=work` 时为作品 id；`kind=series` 时为曲目 id。 |
| `title` | string | 包标题。**保持作品原标题不变**（章节标识只体现在下载文件名上）。 |
| `summary` | string | 简介文本。 |
| `author` | string | 作者名。 |
| `series` | object \| null | `kind=work` 时写所属曲目 `{ "id": "...", "title": "..." }`；`kind=series` 时为 `null`。 |
| `license` | object | 许可证，见 §7。 |
| `engine` | object | `{ "minVersion": 1 }`，运行该包所需的暮幕能力版本。 |
| `works` | array | 作品数组，**至少 1 条**，见 §4.2。 |
| `assets` | array | 资源数组，可为空，见 §4.3。 |
| `createdAt` | string | ISO 时间戳（导出时刻）。 |
| `generator` | string | 固定为 `暮幕 MuMU`。 |

### 4.2 `works[]` 每一条

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 作品 id（导入后作为本地 id）。 |
| `title` | string | 作品标题。 |
| `tag` | string | 章节标签，曲目卡上的短标题。 |
| `chapterNo` | number | 章序。 |
| `file` | string | 相对包内的文本路径（`script.txt` 或 `chapters/01.txt`）。 |
| `format` | string | 固定 `text`（暮幕 DSL）；`json` 为预留值。 |
| `chars` | number | 正文字数（不含空白），导出时按 `countChars()` 统计。 |

**`chapterNo` 的口径**：接受**可转成整数的数字字符串**（`'2'` → `2`）；缺失或非法
（`undefined` / `'oops'` / `0` / 负数）时回退为按顺序补位（下标 + 1）。导出侧同样用
`Number()` 归一，两边语义一致。**包内章序应连续且唯一**（1、2、3……）：导入端**保留**
包内写下的章序，不会自动重排；章序有缺口时由**导出端**整理成连续的 1、2、3……，
所以「以哪一份为准」取决于方向——导入看包里写的，导出看暮幕排出来的。

### 4.3 `assets[]` 每一条

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 资源 id，目前封面为 `cover`。 |
| `role` | string | 目前仅 `cover`。 |
| `file` | string | 相对包内的资源路径。 |
| `type` | string | MIME，按扩展名推断（`jpg`/`jpeg`/`png`/`webp`）。 |
| `bytes` | number | 资源字节数。 |

### 4.4 缺省与容错

导入时（`validateManifest`）对缺省字段的兜底：

| 情形 | 处理 |
| --- | --- |
| `works` 为空或不是数组 | **报错**「作品包里没有作品。」 |
| 某条 `works[].file` 缺失 | **报错**「作品包缺少第 N 章的剧本文件。」 |
| 某条 `works[].id` 缺失 | 回填为 `chapter_N`（N 为下标 + 1） |
| 某条 `works[].title` 缺失 | 回填为该条的 `id` |
| 某条 `works[].tag` 缺失 | 回填为该条的 `title` |
| 某条 `works[].chapterNo` 缺失或非法 | 回填为下标 + 1（见 §4.2） |
| 某条 `works[].format` 缺失 | 回填为 `text` |
| 某条 `works[].chars` 缺失或不是数字 | 回填为 `0` |
| `summary` / `author` 缺失 | 回填为空串 |
| `series` 缺失 | 回填为 `null` |
| `kind` 缺失 | 作品数 > 1 判为 `series`，否则 `work` |
| `assets` 缺失或不是数组 | 回填为空数组 |
| `license` 缺失或字段不全 | 见 §7 的兜底规则 |
| **manifest 里有不认识的字段** | **忽略但不报错**（保证向前兼容，新版本暮幕写的包旧版也能读） |

## 5. schema 版本与迁移规则

包上有两个版本号：`formatVersion` 管**容器布局**（ZIP 里怎么摆文件），
`schemaVersion` 管**内容结构**（manifest 里有哪些字段）。

导入流程固定为：

```
读 manifest → 校验 format / formatVersion → 循环 MIGRATIONS 直到 schemaVersion 收敛
→ 校验 works → 逐章解析文本 → 落库
```

- 迁移表：`MIGRATIONS = { 1: migrateV1toV2 }`。
- `manifest` **没写 `schemaVersion`** 时按 v1 处理，方便读老形状的包。
- 循环迁移最多 10 轮，防止互相引用导致死循环。

### 5.1 v1（草案）→ v2 迁移

v1 是本格式确定前的草案形状，保留下来是为了验证迁移链真的能跑：

```jsonc
{
  "format": "mumu-package", "formatVersion": 1, "schemaVersion": 1,
  "id": "x", "title": "x",
  "chapters": [ { "id": "c1", "title": "c1", "file": "script.txt" } ],  // 没有 works 包装
  "assets": { "cover": "assets/cover.jpg" }                             // 对象映射而非数组
}
```

`migrateV1toV2(manifest)` 做这些事：

- `chapters` → `works`，逐条补 `tag`（取 `title`）、`chapterNo`（缺失或非法时按下标 + 1）、
  `format: "text"`、`chars: 0`；
- `assets` 对象映射 → `assets` 数组，逐条补 `id` / `role` / `type`（按扩展名推断）/ `bytes: 0`；
- 补 `kind`（作品数 > 1 → `series`，否则 `work`）、`series: null`、`summary: ""`、`author: ""`、
  默认 `license`、`engine: { "minVersion": 1 }`；
- `schemaVersion` 置为 `2`。

> 迁移**不**兜 `file`：缺 `file` 的条目会原样保留，由校验环节报错拦下。

### 5.2 版本太新怎么办

包的 `formatVersion` 或 `schemaVersion` 高于当前暮幕支持的版本时，导入直接拒绝并给出中文
提示（见 §11），不会「尽力而为」地读一半。

## 6. 剧本 DSL 速查

作品包里的剧本文本就是**暮幕剧本格式**（`.txt` / `.md`）。导入弹窗里给出的示例
（`scripts/parser.js` 的 `FORMAT_EXAMPLE`）是标准范本：

```
标题：蝉鸣止于逢魔时（示例）
简介：放学后的教室，一段没来得及听完的录音。
角色：
夏目悠真 | 男 | 短发 | 藏青 | 少年
小葵 | 女 | 双马尾 | 橙 | 少女
小悠真 | 男 | 短发 | 灰 | 男儿童

【场景：教室 | 黄昏 | 远景】
夕阳把课桌的影子拉得很长，风从半开的窗户钻进来，翻动没人收拾的练习册。
蝉声在窗外连成一片，像谁把夏天按下了循环播放。

【场景：教室 | 黄昏 | 中景】
夏目悠真：……谁把录音带落在这儿了？
小葵：悠真哥，你终于来了！
小葵（录音）：如果明天还能见面，我想把这首歌听完。

【镜头：特写】
夏目悠真：磁带上贴着一张便签，字迹被汗水晕开了一点。

【镜头：中景】
> 追问小葵录音的事 -> ask
> 假装没注意，把磁带放进口袋 -> keep

[ask]
小葵（难过）：那不是我录的……
-> ending

[keep]
【清场】
【场景：操场 | 夜晚 | 远景】
操场的灯一盏一盏亮起来，蝉鸣却忽然停了。
-> ending

[ending]
【结束】
```

### 6.1 写法速查表

| 写法 | 含义 |
| --- | --- |
| `标题：xxx` / `简介：xxx` / `作者：xxx` | 元信息，可省略 |
| `角色：` | 角色块开始；下面每行一个角色，**遇到任何非角色行自动结束** |
| `名字 \| 性别 \| 发型 \| 衣色 \| 模型` | 角色定义；第五列（模型）可省略 |
| `【场景：X \| 时间 \| 镜头】`（或 `【分镜：…】`） | 切换分镜；只有 `X` 必填，其余缺省为「黄昏 / 中景」 |
| `【镜头：远景\|中景\|近景\|特写】` | 中途只改景别 |
| `【姿态：难过】` / `【情绪：难过】` | 身体语言；可写 `【姿态：林夏\|难过】` 只作用于某人 |
| `【动作：坐下】` | 动作；可写 `【动作：林夏\|坐下】` |
| `【视角：过肩】`（或 `【机位：…】`） | 视角；常规 / 过肩 / 背影 |
| `【出场：小悠真\|小葵】`（或 `【登场：…】`） | 让指定角色先站上舞台但不发言 |
| `【清场】`（或 `【空场】`/`【无人】`） | 所有人物退场，只留场景 |
| `【结束】`（或 `【完】`/`【结束：结局名】`） | 收尾 |
| `[标签]` | 落点定义 |
| `-> 标签` | 跳转 |
| `> 选项文字 -> 标签` | 选项；**同一组选项连续写多行** |
| `名字：台词` | 对白 |
| `名字（开心）：台词` | 行内情绪，只影响这一句 |
| `名字（录音）：台词` | 画外音：只显示名字，人物不出场 |
| `名字（轻声）：台词` | 语气备注，不生成假角色 |
| 没有名字的行 | 旁白 |
| `// 注释` 或 `<!-- 注释 -->` | 注释行，忽略 |

> （所以「火夜」不会被「夜」抢先识别成夜晚）。

### 6.3 特写道具的匹配优先级

`【镜头：特写】` 会根据**紧邻特写的那句台词 / 旁白**挑一个道具来画。匹配是
**按固定顺序、命中即止**（第一条命中的规则胜出），所以一句话里同时出现多个物件时，
靠前规则的物件会被画出来。想换道具，就让那句话只提你想画的那一个。

当前顺序（`scripts/prop.js` 的 `pickProp()`，从前往后）：

碎片 → 手机 → 放大镜 → 星图 → 账本 → 档案袋 → **令牌（玄铁 / 虎符）** →
**青铜雕塑（雕塑 / 铜像 / 雕像）** → 咖啡 → 戒指 → 橘子汽水 → 小提琴 → 乐谱 →
钢琴键盘 → 《星月夜》画作 → 长卷 → 紫檀木盒 → 研钵颜料 → 旧照片 → 耳机 →
信纸 → 文件纸张 → 磁带随身听。

两个容易踩的例子：

- 「玄铁令牌放在**青铜**镇纸旁」→ 画**令牌**（令牌规则排在青铜雕塑前面）。
- 「倒下的**青铜雕塑**旁散落着文件」→ 画**青铜雕塑**（雕塑规则排在文件纸张前面）。

一条都没命中时**不画道具**，镜头只留场景。

### 6.4 写作注意

- **角色行判定**：含 `|`、不是 `【…】`、且**第一个 `|` 之前不含冒号**，才算角色行。
  台词里出现 `|`（如「阿蓝：这个 | 那个」）不会被误吞。
- 角色块里写 `名字 |` 这样的行是安全的；只写「名字」会被当成台词或旁白。
- 纯环境描写的段落不要写台词，画面就只留场景。
- 剧本必须至少有一句台词或旁白，否则解析失败。

## 7. 许可证字段与二创规则

`license` 三个字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `type` | string | 许可证类型，自由文本，例如 `署名-非商业`、`CC BY-NC 4.0`。 |
| `holder` | string | 权利人（作者名）。 |
| `allowRemix` | boolean | 是否允许他人改编。 |

**缺省兜底**：`type` 缺失或为空 → `未指定`；`holder` 缺失或为空 → `未署名`；
`allowRemix` 不是布尔值 → `true`。**这三项缺失都不会阻断导入。**

二创规则：

- `allowRemix: true` 表示允许改编，**改编需保留来源署名**（包内 `LICENSE.txt` 会写
  「允许改编（改编需保留来源署名）」）。
- `allowRemix: false` 表示不允许改编（`LICENSE.txt` 写「不允许改编」）。
- 暮幕**不强制执行** `allowRemix`：导入端只把它当作声明性元数据存进作品的
  `manifest` 快照，靠人守规矩，不是靠程序拦截。

> **注意**：从界面导出的包，`license` 固定是默认值（`未指定 / 未署名 / true`），
> 因此**不会**生成 `LICENSE.txt`。要带上真实许可证，需要手工编辑包内 `manifest.json`
> 的 `license` 字段后重新打包。

## 8. 导出：文件名、限额与提示

### 8.1 下载文件名规则

| 导出方式 | 文件名 |
| --- | --- |
| 整本（曲目卡「导出整本」） | `曲目标题.mumu` |
| 单章（独立卡「导出 .mumu」/ 章节行「导出」） | `曲目标题 · 章节标识.mumu` |

- **章节标识**取该章的 `tag`；没有 `tag` 时用 `第N章`（如 `第2章`）。
- 章节标识最长 40 字，超出截断。
- **包内的 `title` 保持作品原标题不变**——只有下载文件名带章节标识，导入后的卡片标题
  不会被改写。
- 文件名里的 Windows 非法字符 `[\\/:*?"<>|]` 会被替换成 `_`；结尾的点与空格会被去掉；
  曲目标题部分最长 80 字、章节标识最长 40 字；命中 Windows 保留名
  （`CON` / `PRN` / `AUX` / `NUL` / `COM1`…）时会加 `_` 前缀。

### 8.2 体积限额

| 项 | 限额 | 超限处理 |
| --- | --- | --- |
| 整包体积 | 32MB | 导出时拦截：「作品包超过 32MB，请缩减内容后再导出。」；导入时拒绝：「作品包超过 32MB，无法导入。」 |
| 单个资源（封面） | 4MB | 跳过封面并给出警告（见 §8.3），包仍可导入 |
| 解压后总体积 | 64MB | 拒绝导入：「作品包解压后的内容超过 64MB，请缩减内容后再导入。」 |
| 单章剧本文本 | 5MB | 拒绝导入：「第 N 章的剧本文件超过 5MB，请拆分后再导入。」 |
| 单章剧本文本字数 | 30000 字 | 导入时拒绝：「第 N 章的剧本有 N 字，超过上限 30000 字，请精简后再导入。」；导出时同样拦截：「《xxx》的剧本有 N 字，超过上限 30000 字，请精简后再导出。」 |

> **5MB 是字节数，30000 字是字数，两道限制都要过。** 文本导入（`.txt` / `.md`）另有一层字数下限
> （200 字），作品包导入只卡上限、不卡下限——短小的一章是可以的。
>
> **导出侧也卡 30000 字**：这样「导出的包一定能被自己导回来」，不会出现导得出去、导不回来的包。

### 8.3 导出提示（warnings）

导出成功后会依次弹出提示：

- `已导出《xxx.mumu》`；
- 若该作品**没有保留原文**（早期导入的剧本、或从 JSON 导入的剧本），额外提示
  「该剧本没有原文，导出为重建文本（内容可能与原文略有差异）。」；
- 然后是本次导出的 `warnings`（见下表）。

导出侧的封面警告：

| 情况 | 文案 |
| --- | --- |
| 封面图不是 PNG / JPEG / WebP | 封面图片格式无法识别，已跳过封面。 |
| 封面图超过 4MB | 封面图片超过 4MB，已跳过封面。 |

### 8.4 导出侧错误

| 情况 | 文案 |
| --- | --- |
| 没有可导出的作品 | 没有可导出的作品。 |
| 单章导出却传了多个作品 | 单章导出只支持一个作品，请改为导出整本。 |
| 作品既没有原文、也无法重建文本 | 《xxx》没有可导出的文本内容。 |
| 打包后超过 32MB | 作品包超过 32MB，请缩减内容后再导出。 |
| 重建文本时遇到不认识的节点类型 | 未知的节点类型“xxx”，无法导出为剧本文本。 |
| 某章字数超过 30000 字 | 《xxx》的剧本有 N 字，超过上限 30000 字，请精简后再导出。 |

## 9. 导入：落库、冲突与提示

### 9.1 导入做了什么

1. 读 `ArrayBuffer`，校验体积 ≤ 32MB。
2. 解压 ZIP，取全部条目为 `Map<条目名, 字节>`；累计解压后体积，超 64MB 就拒绝。
3. 取 `manifest.json`，UTF-8 解码 + `JSON.parse`。
4. 校验并迁移 manifest（§5）。
5. 逐条解析 `works[]`：用 `parseScriptText(text, 标题)`，解析器的老格式与标签全部照旧生效。
6. 处理 id / 曲目冲突（§9.2）。
7. 封面：`assets` 里 `role === "cover"`（或 `id === "cover"`）的那一条 → 字节 → data URL；
   写库前缩到最长边 640px 的 JPEG。
8. 逐条 `addCustomScript` 写进 `mumu.scripts.v1`，刷新剧本库。

**导入失败不写入任何数据**：任何一步失败都会抛出中文错误，整个包一个字节都不落库。

### 9.2 同名冲突怎么办

导入的作品**绝不会覆盖内置剧本**（内置 id 一律是 `builtin_*`）：

| 情况 | 处理 |
| --- | --- |
| 作品 id 与**本地已导入**作品相同，且归属同一个曲目 | 视为**更新**，覆盖同 id 记录 |
| 作品 id 与**内置**作品相同（或以 `builtin_` 开头） | 加 `user:` 前缀另存 |
| 作品 id 与**别的曲目**下的本地作品相同 | 改名 `user:<id>` 另存 |
| 同一个包内 id 重复 | 自动加后缀避让（`id_2`、`id_3`…） |
| 整本包的曲目 id 与本地曲目（含内置曲目）冲突 | 曲目 id 加 `user:` 前缀（如 `user:cicada`），整本作为**新曲目卡**出现；已是 `user:` 前缀的视为同一曲目，按更新处理 |
| 单章包（`kind=work`） | **始终**是独立卡片，不并入任何曲目；包内 `series` 字段只作为来源信息存进 `manifest` 快照 |

### 9.3 导入提示（warnings）

导入成功后会依次弹出：`已导入《xxx》，共 N 章`，然后是本次导入的 `warnings`。

| 情况 | 文案 |
| --- | --- |
| 封面条目声明了 `file` 但包里没有这个文件 | 作品包内没有封面文件，已跳过封面。 |
| 封面文件超过 4MB | 封面图片超过 4MB，已跳过封面。 |
| 封面图处理失败（缩放与兜底都失败） | 封面图片处理失败，已跳过封面。 |
| `assets` 里有个像封面的条目，但认不出来 | 作品包内的封面条目无法识别，已跳过封面。 |

**有 warning 不等于导入失败**：作品照样入库，只是封面没带上。

### 9.4 提示是排队的

导出 / 导入的提示改成**队列**：连续多条提示会依次显示，后一条要等前一条消失才出现，
不会互相覆盖。导入多章作品包时出现连续几条提示属正常行为。

## 10. 已知限制

### 10.1 ZIP 层（`scripts/zip.js`）

暮幕的 ZIP 实现是自写的最小实现，边界如下：

- **条目名用 UTF-8 存储**：写入时置通用标志位 bit 11（`0x0800`），读取时一律按 UTF-8
  解码条目名，中文名不乱码。
- **不支持 ZIP64**：大小与偏移都是 32 位字段，单文件或总大小超过 4GB 的包读写不了。
  本作的包上限是 32MB，实际不会碰到。
- **只支持两种压缩方式**：`stored`（method 0）与 `deflate-raw`（method 8）。
  写入时优先 `deflate-raw`，压不小或环境不支持 `CompressionStream` 时退回 `stored`；
  读到其它压缩方式会报「压缩包使用了不支持的压缩方式。」
- **不做路径规范化，也不拒绝带 `..` 的条目名**。实际风险很低：导入端只按 manifest
  里声明的路径做**精确匹配**（`manifest.json`、封面、`works[].file`），全程不落盘解包，
  不会写到文件系统以外的地方。
- 依赖浏览器内置的 `CompressionStream` / `DecompressionStream`；老浏览器不支持
  `deflate-raw` 时会提示「当前浏览器不支持解压 zip，请升级到较新的浏览器，或直接导入
  .txt 文件。」

### 10.2 序列化兜底的有损边界（`scripts/serialize.js`）

导入作品时会保留**原文**；只有早期导入的剧本没有原文，才用 `serializeScript()` 把解析
结果重建成 DSL 文本作为导出兜底。重建不是无损的，作者须知边界：

- **台词里出现 `|` 时要自己核对成品**。`|` 在「角色：」块里是列分隔符；解析器按
  「第一个 `|` 之前不含冒号才算角色行」判定，但「角色：」块内**不含冒号且含 `|`** 的行
  仍会按角色行处理——这是既有行为，不是新回归。
- **行内语气备注可能变成情绪**：括号里恰好写的是情绪别名（如「开心」）时，重建出的文本
  会被解析成情绪节点，而不是语气备注。
- **角色行会裁掉末尾的空列**：只剩名字时保留「名字 |」的形式（去掉竖线会被当成台词）。
- **节点类型不被支持时导出会直接报中文错误**（带 `userFacing = true`，
  「未知的节点类型“xxx”，无法导出为剧本文本。」），而不是导出一份坏文本。
- 从 **JSON** 导入的剧本不保留原文（JSON 不是暮幕 DSL，写进包里的 `script.txt` 导入
  必然失败），导出时必然走重建文本。

## 11. 常见报错与处理

### 11.1 导入 `.mumu` 时的报错

报错显示在导入弹窗内的红色文案里。

| 情况 | 文案 | 处理 |
| --- | --- | --- |
| 包超过 32MB | 作品包超过 32MB，无法导入。 | 拆成单章包，或删掉封面。 |
| 读到的不是有效缓冲区 | 作品包数据无效，无法导入。 | 重新下载 / 传输一次。 |

| manifest 不是合法 JSON | 作品包清单无法解析，可能已损坏。 | 重新导出。 |
| `format` 不符 | 这不是暮幕作品包。 | 同上。 |

> （ZIP 结构无法读取）。」；只有导入 `.zip` 剧本时才会看到 ZIP 层的原始文案。

## 12. 库内管理与存储配额

### 12.1 剧本库里的动作

| 位置 | 动作 | 说明 |
| --- | --- | --- |
| 独立卡（单章作品） | 「导出 .mumu」/「移除」 | 非内置作品才有这两个按钮，并带「已导入」徽标 |
| 曲目卡 | 「导出整本」 | 所有曲目卡都有 |
| 曲目卡 | 「移除整本」 | **只有非内置的曲目卡**才有；内置曲目不可移除 |
| 曲目卡 | 「已导入」徽标 | 组里只要有一章不是内置就显示 |
| 章节列表的每一行 | 「导出」 | 导出该章的单章包 |

**移除只在浏览器本地生效**：删掉的是 `mumu.scripts.v1` 里的本地记录，
不会影响导出出去的 `.mumu` 文件，也不会动内置剧本。「移除整本」只删该曲目里**非内置**
的那些章节。

### 12.2 存储配额

浏览器 localStorage 容量有限（常见在 5MB 量级）。导入整本或带大封面的包可能写不下，
这种情况**不会谎报成功**：

- 文本导入写不下：`浏览器存储空间不足，剧本没有保存成功。`
- 作品包部分章节写不下：`浏览器存储空间不足，N 章中有 M 章没有保存成功。`
  （已经存进去的章节照样能看到、照样能演。）
- 存档写不下：`浏览器存储空间不足，进度没有保存成功。`

**处理办法**：先移除部分剧本腾出空间，再重新导入。

封面入库前会被缩到**最长边 640px 的 JPEG**（浏览器环境，quality 0.82），所以单个封面
通常只有几十 KB。缩放失败时，若原图不超过 2MB 就直接用原图，否则跳过封面。

存档上限 40 条，超出的旧存档会被丢弃。

**旧存档（`mumu.saves.v1`）的读取口径**：暮幕先读 `mumu.saves.v2`；只有在**没有**任何
v2 存档时，才去读 `mumu.saves.v1` 并把它迁移成 v2（补齐 `version` / `state` 等新字段）。
也就是说两代并存时以 v2 为准，旧存档不会被自动合并进来——这是既有的存储策略，
不是导入作品包带来的变化。
