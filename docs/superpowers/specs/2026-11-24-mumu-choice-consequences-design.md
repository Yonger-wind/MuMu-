# 选择有后果（P2-2）设计

- 版本：v1.0
- 日期：2026-11-24
- 状态：比赛版必做项，设计待落计划
- 上位文档：`docs/superpowers/specs/2026-11-23-mumu-local-creation-platform-roadmap.md` v2.1 §0.1、§1 第 1 项、P2-2 行

## 0. 一句话

选项可以写入布尔旗标；后续台词与舞台指示可以按旗标条件播放；旗标在「继续下一章」时带入同曲目下一章。不改内置剧本的结局结构，不新增多结局。

## 1. 目标与非目标

### 1.1 目标

1. 玩家做过的选择，能在同一章后续产生**可看见**的差异：不同台词、不同特写道具、不同构图/站位、不同光影。
2. 演示主线《蝉鸣止于逢魔时》第一章的三个选项都带后果；第二章开场能读到第一章的旗标。
3. 作者可以在现有文本 DSL 里直接写，不需要代码、不需要新依赖。
4. 旧剧本零改动照常播放；旧存档（无 `flags`）照常读；导出/导入往返不丢新语法。
5. 解析、引擎、校验器、序列化四个环节对同一套语法口径一致。

### 1.2 非目标（本阶段明确不做）

- 不做多结局、不做 `endingId` 分支改造（P2-1 已砍，内置剧本结局结构保持原样）。
- 不做数值/字符串旗标比较、不做 AND/OR、不做条件选项、条件跳转、条件标签。
- 不做可视化分支编辑器（P2-3 延后）。
- 不做跨会话的旗标持久化（P3-1 只负责“当前节点”自动存档；旗标随存档快照走）。
- 不做新 UI：选择回响用台词体现，不新增“选择记录”面板。
- 不修改渲染器；站位/光影/道具全部复用现有 `scene/time/cam/cast/view/propText` 通道。
- JSON 剧本输入暂不支持新语法；只支持文本 DSL 与内置剧本（导出会把节点还原成文本 DSL）。

## 3. 语法

### 3.1 选项写入旗标

```text
> 追问她：“你真的只是觉得怀旧吗？” @asked_tape -> ask
> 假装没注意，低头继续修磁带 @kept_quiet -> ignore
```

- `@` 注解只能出现在选项文字的**末尾**、`->` 之前。
- 一个选项可写多个旗标：`@flag_a,flag_b`。
- 键名：`[A-Za-z][A-Za-z0-9_]{0,31}`，区分大小写，推荐 snake_case。
- 选项文字里不在末尾的 `@` 不受影响；末尾形如 `@...` 但键名非法时报中文错误，不静默当文本。
- 旗标是布尔值：选中即置 `true`；不提供“取消”语法。互斥由作者用两个不同旗标表达。

### 3.2 条件行

```text
?? asked_tape | 白石葵（轻声）：刚才你那样追问，我差点就藏不住了。
?? !asked_tape | 旁白：她似乎松了一口气。
?? asked_tape | 【视角：过肩】
?? picked_papers | 【镜头：特写】
```

- 行首 `??` + 一个条件 + `|` + 一行原有内容。
- 条件：`key`（为真）或 `!key`（为假/不存在）。
- 只按**第一个** `|` 切开；之后的内容整体按原有规则解析：台词/旁白，或舞台指示。因此 `?? asked_tape | 【场景：操场 | 黄昏 | 远景】` 里的内层 `|` 属于场景标签本身。
- 允许条件的舞台指示：场景/分镜、镜头、姿态/情绪、动作、视角/机位、出场/登场、清场/空场/无人。
- 不允许：结束/完、选项、跳转、标签、标题/简介/作者、角色表行。遇到时报中文解析错误，并给出行号与允许范围。
- 条件不改变控制流：条件为假时引擎跳过该节点，继续下一个节点；不产生额外跳转。

### 3.3 为什么是这两个记号

- `@` 不与 `>`、`->`、`[]`、`【】` 冲突；选项仍是单行，作者无需记块结构。
- `??` 单独占行首，不会与台词里的问号混淆；条件行可以逐行读，不需要配对的结束标签。
- 否决的方案：
  - 块式 `【如果】…【否则】…【结束如果】`：解析器要维护嵌套栈，校验器要复刻块匹配，成本高、错误面大。
  - `【旗标：k=v】` 写在目标标签里：可行，但把“选择”和“写入”拆成两处，选项一多就难对账，且仍要另一套条件语法。
  - 复用 `vars` 做字符串比较：P2-2 只需要“发生过/没发生过”，布尔足够。

## 4. 解析器

- 选项：解析出 `{ text, to, set?: string[] }`；`text` 不含 `@` 注解。
- 节点：任何被允许的节点可带 `cond?: { key: string, neg: boolean }`。
- 实现方式：每行先剥条件前缀；该行若产出节点，则把 `cond` 挂到节点上。标签/选项/跳转在带条件时直接报错。
- 文本行数、标签落点、`flushChoices()` 的既有语义不变。
- `finalize()` 的标签存在性、补场景、补结束逻辑不变。
- JSON 输入不解析 `@` / `??`；导出走 `serializeScript()` 生成文本 DSL。

## 5. 引擎与状态

- 循环顶部：`if (n.cond && !condOk(n.cond)) { idx++; continue; }`。
  - `condOk` 用现有 `getFlag(key)`；`neg` 时取反。
- 选择回调：在跳转前，把 `option.set` 里每个键写为 `state.flags[key] = true`。
  - 检查点在选项 UI 出现前已入栈，因此 `rewind()` 回到选项时，上一次选择写入的旗标会被一并回滚。
- 存档：`snapshot()` 已经 `cloneState(state)`，无需改结构；旧档 `deserializeState` 补 `{}`。
- 章节结束：保持原样，不因旗标改变结局节点。

## 6. 跨章携带

- `engine.start(sc, snapshot = null, carry = null)`：
  - `snapshot` 存在时，以 `snapshot.state` 为准（含 flags）。
  - 否则若 `carry` 存在，把 `carry` 浅拷贝进新 `state.flags`。
  - `carry` 只带旗标；`choices / checkpoints / vars / endingId` 不跨章。
- `main.js`：
  - `play(script, snapshot = null, carry = null)` → `engine.start(script, snapshot, carry)`。
  - 「继续下一章」：`play(next, null, { ...engine.state.flags })`。
- 直接从章节列表进入、或「重新开始」：不携带，旗标从空开始。
- 读档：`snapshot.state.flags` 恢复，因此章节内读档后条件仍生效。
- 已知限制：刷新页面后直接进入第二章不会继承第一章旗标；P3-1 只保证当前节点续玩，不扩旗标持久化。正常“第一章→继续下一章”链路可用。

## 7. 画面差异如何落地（不渲染器改动）

| 需求 | 写法 | 引擎/渲染器现有通道 |
| --- | --- | --- |
| 不同台词/选择回响 | `?? flag | 角色：…` | 条件跳过 `say` |
| 光影 | `?? flag | 【场景：操场 | 黄昏 | 远景】` | `scene/time` → `PALETTES`，换场景自动失效图层 |
| 构图/站位 | `?? flag | 【视角：过肩】`、`?? flag | 【镜头：近景】`、`?? flag | 【出场：A|B】`、`?? flag | 【清场】` | `actState.view`（`over` 需 ≥2 人）、`cam`、`cast` |
| 特写道具 | `?? flag | 【镜头：特写】` + 下一句条件台词含道具词 | `propText` → `pickProp` |
| 表情/动作 | `?? flag | 【姿态：…】` / `【动作：…】` | `poses/actions`（既有转发通道） |

说明：`poses`/`actions` 目前渲染器未真正消费（仅转发）；`view` 只实现了 `over`，`back` 目前与 `normal` 画面相同（`scripts/scene.js:16025` 只有过肩分支）。P2-2 不承诺表情差异，演示只使用光影/构图（过肩、近景）/道具/台词四类可见差异。

## 8. 演示内容（《蝉鸣止于逢魔时》）

### 8.1 第一章

三个选项各写入一对互斥旗标：

| 选项 | 旗标 |
| --- | --- |
| 追问她 | `asked_tape` |
| 假装没注意 | `kept_quiet` |
| 为什么不早点说 | `asked_why` |
| 至少今天把歌听完 | `chose_song` |
| 先捡文件 | `picked_papers` |
| 抓起就跑 | `grabbed_run` |

在 `[dash]` 之后、结尾夜戏之前插入条件段：

- 选择回响：`asked_tape` / `kept_quiet` 各一句白石葵的回应；`asked_why` / `chose_song` 各一句夏目的回应；`picked_papers` / `grabbed_run` 各一句呼应。

- 道具：`picked_papers` → `【镜头：特写】` + “转学文件”台词（`paper`）；`grabbed_run` → `【镜头：特写】` + “随身听/磁带盒”台词（`cassette`），随后各自恢复 `【镜头：中景】`。

- 不新增结局、不改 `[ask] [ignore] [fix] [why] [song] [offer] [papers] [run] [dash]` 的收敛关系。

## 9. 校验器（lint）

- 扫描器先剥 `??` 前缀再分类；条件语法错误报 **E109**。
- 条件用在不允许的行（选项/跳转/标签/结束/meta/角色行）报 **E109**。
- 选项 `@` 注解键名非法报 **E110**；注解不改变选项落点校验。
- 不检查“旗标是否从未被写入”：跨章旗标（如第二章读第一章的 `asked_tape`）在单章文本里看起来就是未写入，静态告警会误报。拼写错误由演示与人工回归兜底。
- 控制流图仍按节点序列推导；条件节点不产生新边。
- `docs/mumu-lint-rules.md` 补 E109/E110 与语法示例。

## 10. 序列化与作品包

- `serializeScript()`：
  - 带 `cond` 的节点行首输出 `?? key | ` 或 `?? !key | `。
  - 带 `set` 的选项输出 `> 文本 @a,b -> 标签`。
  - 无新字段时输出与现在完全一致（逐字节兼容现有导出）。
- 导出→导入→再解析的往返必须保留 `cond/set`。
- 作品包 manifest 不变；无需提升 schema 版本。

## 11. 错误与兼容

- 新语法的错误一律 `userFacing` 中文，带原始行号。
- 旧文本（无 `@`/`??`）解析结果不出现 `cond/set` 字段，行为零变化。
- 旧存档缺 `flags` → `{}`；条件按“未发生”处理。
- 选项文字里普通 `@`（不在末尾注解位）不做处理。
- 条件引用未写入旗标时引擎按假处理；lint 不对此告警（跨章引用合理）。

## 13. 风险与取舍

| 风险 | 取舍 |
| --- | --- |
| 条件语法增加解析/校验双实现漂移 | 解析器与 lint 共用同一套正则常量（导出供 lint 引用），测试锁住合法/非法样例 |

## 15. 裁决记录

- Ruling: 旗标只做布尔，不做值比较 — P2-2 只需“发生过/没发生”，布尔让语法、存储、lint 都最小 — 若判断错，未来要加值比较时需扩语法与测试。
- Ruling: 条件只允许单条件，不支持 AND/OR — 演示与比赛需求用互斥旗标即可表达，块条件成本高 — 若判断错，复杂条件需拆成多条条件行。
- Ruling: 条件不用于选项/跳转/标签 — 避免控制流图、回退检查点、lint 可达性同时复杂化 — 若判断错，作者需用旗标+普通跳转绕行。
- Ruling: 跨章只带旗标，不落盘 — 与 P3-1 范围解耦，正常连续游玩可用 — 若判断错，刷新后跨章后果丢失（已写入限制）。
- Ruling: 不加新 UI，选择回响用台词体现 — 不碰既有布局与交互，风险最低 — 若判断错，评审时需要靠台词/画面辨认后果。
- Ruling: 演示里「安静路线」用 `【镜头：近景】` 而不是 `【视角：背影】` — 渲染器只实现 `over`，`back` 与常规画面相同，改渲染器超出本阶段 — 若将来实现背影，可把演示改回 `背影` 并补测试。
