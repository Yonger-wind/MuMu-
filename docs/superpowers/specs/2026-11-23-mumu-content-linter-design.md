## 1. 目标与背景

### 1.1 问题

暮幕的剧本 DSL 由作者（或 AI）手写。解析器 `scripts/parser.js` 的容错策略是「宁可放过，不要挡住」：

| 写法 | 解析器当前行为 | 后果 |
| --- | --- | --- |
| `【未知标签：特写】` | 未知指示 fallthrough 成旁白 | 作者以为设了镜头，实际没生效，**静默** |
| `【镜头：超特写】` | 词表匹配回落 `mid` | 镜头被悄悄改掉，**静默** |
| `【姿态：崩溃】` | 回落 `neutral` | 姿态被悄悄改掉，**静默** |
| 角色表第五列写错模型名 | `matchModel` 返回空 → 按性别回落 | 外观与预期不符，**静默** |
| `> 选项文本`（漏写 `-> 落点`） | 整行退化为旁白 | 选项凭空消失，**静默** |
| `[标签]` 重复定义 | 后者覆盖前者 | 分支走向与预期不符，**静默** |
| 跳转指向不存在的标签 | 抛错，但**不带行号** | 用户拿到一句「跳转指向了不存在的标签「x」」，不知道在哪一行 |
| 场景名写错 | 抛错，**带行号** | 唯一会准确定位的一类 |
| 某段落在跳转之后，再无人能走到 | 正常解析 | 玩家永远看不到那段，**静默** |

也就是说：**真正会「炸」的写法会报错但难定位；真正会「悄悄错」的写法完全不报错。** P0-3 要补的就是后半截。

### 1.2 目标

给剧本作者一个零依赖的静态检查器，让写坏的剧本在**导入之前**就被拦下，并且每条问题都带**行号 + 原因 + 修法提示**。

完成定义（沿用路线图 P0-3 行）：

1. `node tools/lint.js --builtin` 对内置 15 章 **零 error、零 warning**。
2. 对故意写坏的小样本能报出**行号与原因**。
3. 不破坏剧本解析、人物识别、对话播放、分支、存档、分镜与作品包链路。

### 1.3 非目标

- 不做自动修复（`--fix`）：作者改了剧本还要再审一遍，修复语义比报错复杂，收益不抵成本。
- 不做 JSON 剧本的行号：JSON 源天然没有行号，报告改用节点序号。
- 不接 `.docx` / `.zip` 源的行号：这些格式的换行语义与源文件不可逆对应，强行给行号只会给出错的行。
- 不引入 CI、不引入第三方依赖、不加构建步骤、不加根 `package.json`。
- **不改动 `scripts/parser.js`**（见 §2、§3）。
- 本期不做编辑器 / 语言服务器 / 实时提示。

## 2. 范围决策

| 议题 | 决策 | 理由 |
| --- | --- | --- |
| 校验范围 | **文本剧本（.txt/.md）+ 内置 15 章** | 内置 15 章是唯一「必须零报错」的语料，是回归基线。JSON/作品包的导入链路由 P0-4 接手，届时把本工具作为前置检查调用即可，不在本期做。 |
| 技术路线 | **文本级扫描器**：校验器自带一套带行号的 DSL 扫描与控制流建图，不碰 `scripts/parser.js` | `scripts/parser.js` 是 `AGENTS.md` 明列保护的运行时核心，改它风险高而收益小：行号完全可以在工具侧自己数出来。代价是扫描器与解析器各有一套判定，必须用「词表一致性测试 + 内置 15 章零 issue」把漂移风险兜住（见 §5.5、§7）。 |
| 规则分级 | **按严重度分级（error / warning）** | 单一等级要么太吵（把「说话人未声明」也算 error，作者根本没法写），要么太松（静默错误漏过）。分级后 CLI 退出码可区分「挡住」与「提醒」。 |
| 接入方式 | **仅 CLI 工具 + 文档**（README + `docs/`） | 导入前置属于 P0-4 的创作链路，仓库自检属于 CI，二者都不在本期范围。工具设计为「可被调用的库 + CLI」，将来接前置只需一行 `await lintText(...)`。 |

> v1.0 曾把技术路线定为「给 parser 节点补行号」，用户选定的是**文本级扫描器**。本版据此重写 §3 / §5 / §9 / §10，`scripts/parser.js` 保持零改动。

## 3. 架构

### 3.1 形态

```
tools/lint.js          新增：校验器（ESM，零依赖，运行时不被 scripts/ 引用）
  ├─ export lintText(text, fileName) → { issues, summary }
  ├─ export lintScript(script, source) → { issues, summary }
  ├─ export lintBuiltin() → { issues, summary }
  └─ CLI: node tools/lint.js <file...> | --builtin [--json] [--strict]

tests/fixtures/lint/   新增：写坏的小样本（文本剧本）
tests/lint.test.mjs    新增：规则单测 + 词表一致性测试 + 内置回归
README.md              改动：新增「内容校验」小节（用法、规则码表、退出码）
docs/mumu-lint-rules.md 新增：面向作者的规则码表与修法说明
```

`tools/` 目录已有的 `png-alpha.js`（CJS，离线素材工具）、`cdp-shoot.cjs`（截图回归工具）都是**不参与游戏运行**的离线工具，`tools/lint.js` 归入同一类：不进 `index.html` 的依赖图，不被 `scripts/` 引用，不影响线上体积。

### 3.2 数据流

```
        原始文本（.txt / .md / 内置章 source）
                 │
      ┌──────────┴───────────┐
      ▼                      ▼
 ① 文本扫描器            ③ 解析器交叉验证
 （自建，逐行，产出      （parseScriptText 只读调用，
   带行号的中间表示）      把抛出的错误兜底成 issue）
      │                      │
      ▼                      │
 ② 控制流建图 + 16 条规则   │
      │                      │
      └──────────┬───────────┘
                 ▼
        issues[]（code / severity / line / message / hint）
                 ▼
        文本输出 或 --json
```

**① 与 ② 是工具内部的两个阶段，同一个文件实现**（`tools/lint.js`），但对外只暴露 `lintText` / `lintScript` / `lintBuiltin` 三个函数。

**③ 是只读兜底**：`parseScriptText` 是纯函数，工具调用它**不产生任何副作用、不修改它**。它的作用是捕捉扫描器可能漏判的硬错误（例如「剧本里没有任何台词」「JSON 格式有误」），避免工具因为自己的一套判定漏掉致命问题。去重规则：若解析器错误发生在某行 L，且扫描器已在 L 行报过 issue，则不重复报。

### 3.3 为什么不需要改 `scripts/parser.js`

行号完全可以由工具自己数：`lint.js` 逐行读文本，记录每行的行号，行号天然就在。控制流（标签 → 跳转 → 选项 → 可达性）也可以在文本层面重建 —— DSL 的这几种结构是稳定的、语法简单的，重建成本远低于改动运行时核心的风险。

代价是「扫描器与解析器各有一套判定」。这个代价用两条测试兜住：

1. **词表一致性测试**：工具内部的词表匹配器必须与 `scripts/parser.js` 的 `matchKey` 在**全部别名与全部内置剧本用到的值**上判定一致（§5.5）。
2. **内置 15 章零 issue**：扫描器对 15 章产出零 issue，说明它的判定没有偏离真实语料；再配合 §3.2 的解析器交叉验证，两边对同一批文本的判断互为印证。

## 4. 规则清单

规则码格式：`E###`（error，会挡住）/ `W###`（warning，提醒）。

### 4.1 Error（8 条）

| 码 | 规则 | 为什么是 error | 报告文案要点 |
| --- | --- | --- | --- |
| E101 | 未知舞台指示标签 | `【未知标签：x】` 会被静默当旁白，作者以为设了镜头/姿态 | 列出本项目认识的 8 类标签名 |
| E102 | 未知场景名 | 解析器直接抛错，剧本必然播不了 | 列出可用场景（截断显示） |
| E103 | 跳转/选项落点标签不存在 | 解析器直接抛错 | 指出行号与目标名，并提示检查 `[目标名]` |
| E104 | 标签重复定义 | 后者覆盖前者，分支静默走错 | 指出两处行号 |
| E105 | 选项行缺少 `-> 落点` | 整行退化为旁白，选项凭空消失 | 给出正确写法示例 |
| E106 | 不可达节点 | 有一段玩家永远走不到（通常是被某次跳转甩在后面） | 指出不可达区间首尾行号 |
| E107 | 跳转目标位于跳转之前（回跳） | 会形成死循环，剧本当场卡死 | 指出两处行号 |
| E108 | 选项落点位于该选项之前（回指） | 玩家点下去原地打转 | 指出两处行号 |

> 已验证：内置 15 章 **零回跳、零回指选项**，所以 E107 / E108 定为 error 不会打破「15 章零报错」基线。

### 4.2 Warning（8 条）

| 码 | 规则 | 为什么只是 warning |
| --- | --- | --- |
| W101 | 未知时间 / 镜头 / 姿态 / 动作 / 视角 | 解析器会静默回落默认值（黄昏 / 中景 / 自然 / 站立 / 常规），画面不对但不会坏 |
| W102 | 未知模型名（角色表第五列） | 会静默按性别回落外观 |
| W103 | 说话人未在角色表声明 | 引擎会自动建角色（新 cid、自动分配外观），能播，但多半是错别字 |
| W104 | `【出场：x】` 中 x 未声明 | 该角色不会出现在人物名单里，出场指令静默失效 |
| W105 | 角色表行列数 ≠ 5 | 解析器取前 5 列，多余列丢弃、缺列取空值，仍能播 |
| W106 | 标签从未被引用 | 多半是作者改了分支忘了删的死标签 |
| W107 | 全文没有任何场景指示 | 引擎会强行补一个「教室 · 黄昏」，多半不是作者想要的 |
| W108 | 结尾没有显式 `【结束】` | 引擎会自动补 `end`，但作者可能忘了写结局说明 |

### 4.3 结局闭合

「结局闭合」在暮幕的模型里由两件事构成，都已覆盖：

- **章节级**：显式 `【结束】` / `【完】` 节点存在（W108 覆盖缺失情形）；解析器自动补的 `end` 不算作者显式收束。
- **分支级**：每个 `choice` 的所有选项都必须有落点且落点可达（E103 / E106 / E107 / E108 覆盖）；一条选择线不能「走一半就掉出剧本」——引擎会把掉出剧本的分支补 `end`，这属于 W108 的范畴。

## 5. 实现要点

### 5.1 文本扫描器（阶段①）

工具内部维护一个「行记录」数组：每行一个记录 `{ line, kind, text }`，`kind` 取值：

| kind | 判定 | 说明 |
| --- | --- | --- |
| `meta` | `^(?:#\s*)?(标题\|简介\|作者)[:：]` | 元信息，不参与角色/台词判定 |
| `charBlockStart` | `^(?:#\s*)?角色[:：]?\s*$` | 角色块开始 |
| `charRow` | 角色块内、含 `|`、且第一个 `\|` 之前不含冒号 | 与解析器 `isCharRow` 同口径（解析器额外排除 `【` 开头的行） |
| `label` | `^\[([^\]]+)\]$` | 标签定义 |
| `dir` | `^【…】$` | 舞台指示 |
| `choice` | 以 `>` 开头 | 选项行 |
| `jump` | 以 `->` 开头 | 跳转行 |
| `say` | 其余非空行 | 台词 / 旁白 |

角色块终止规则与解析器一致：遇到任何非角色行即结束（解析器 `inCharBlock` 遇非角色行置 false）。

### 5.2 词表匹配（阶段①）

词表数据直接复用 `scripts/parser.js` 的导出：

| 需要 | 用什么 |
| --- | --- |
| 场景 | `SCENES` |
| 时间 | `TIMES` |
| 镜头 | `CAMS` |
| 姿态 | `POSES` |
| 动作 | `ACTS` |
| 视角 | `VIEWS` |
| 模型 | `MODELS` + 已导出的 `matchModel()` |

**匹配算法必须在工具内复刻解析器 `matchKey` 的语义**，不能自己简化：

1. 先做**精确别名命中**（把比较串小写后与 `aliases` 比对）；
2. 未命中则取**最长的、作为子串包含在文本里的别名**（同样小写比较）；
3. 仍未命中才算「未知」。

模型同理：剧本里写的是中文 label（`少年`、`少女（2）`），而 `MODELS` 的键是英文 slug（`teen-boy`、`teen-girl-2`），因此**必须走 `matchModel()`，不能查 `MODELS[word]`**。

一致性由 §5.5 的 parity 测试保证。

### 5.3 控制流建图（阶段②）

> **修订（2026-11-24，Task 3 两轮审阅后）**：初版打算用「行级图」，实测发现**行序 ≠ 节点序**——
> 解析器的选项组是**延迟 push** 的（遇到 flush 点才入 `nodes`），而 `【姿态/情绪】【动作】【视角/机位】`
> 这几类指示**不断开**选项组、且会**先于**待定选项组入队。行级图因此会对合法剧本报 error 级假 E106。
> 现改为**复刻解析器节点入队顺序**建图，可达性与标签落点都按**节点下标**推导，再把下标映射回源行号报告。
> 下方条目以修订后的口径为准。

语义对齐 `scripts/parser.js`：

- **节点序列 = 解析器 `nodes` 的入队顺序**。`meta`（标题/简介/作者等）与 `charRow`（角色行）不产生节点，也不断开选项组。
- 选项行 `> 文本 -> 目标` 只挂进待定选项组，**不立即入队**；遇 flush 点先把待定组压成**一个** choice 节点，再压当前行。
  - flush 点：`【场景】`/`【分镜】`、`【镜头】`、`【出场】`/`【登场】`、`【清场】`/`【空场】`/`【无人】`、
    `【结束】`/`【完】`、标签 `[x]`、跳转 `->`、台词 / 旁白（含兜底旁白），以及**文件末尾**的收尾 flush。
  - **不** flush（立即入队、排在待定组之前）：`【姿态】`/`【情绪】`、`【动作】`、`【视角】`/`【机位】`。
- 标签 `[x]` 的落点 = **标签行处「已入队节点数」对应的那个节点**（解析器 `labels[name] = nodes.length`）；
  `finalize` 补场景节点的下标平移不改变相对关系。
- 跳转节点的后继 = 目标节点；选项组节点的后继 = 各选项落点节点（**不含**节点序列里的下一个节点）；
  普通节点的后继 = 节点序列里的下一个节点；`【结束】`/`【完】` 节点无后继。
- 从节点序列第一个节点出发做 DFS，得到可达节点集；报告时把节点映射回**源行号**。

由此判定：

- 不可达节点 → E106（按**节点**切成连续区间，区间内行号**升序**输出，`line` 取最早死行）；
- 跳转行的目标源行号 ≤ 跳转行行号 → E107；
- 选项组内某个选项的落点源行号 ≤ 该组首行 → E108；
- 收集全部被引用的标签，未被引用的标签 → W106；
- 只要存在「跳转/选项指向不存在的标签」，整个文件**不报 E106**（解析器会拒绝该剧本，此时说「走不到」是误导，
  该看 E103）——这是工具的判断，不是解析器语义。


### 5.4 文本级规则

- **E101 未知指示标签**：行首形如 `【xxx：…】`，`xxx` 不在白名单 `{场景, 分镜, 镜头, 姿态, 情绪, 动作, 视角, 机位, 出场, 登场, 清场, 空场, 无人, 结束, 完}` 内。`【结束】` / `【完】` 没有冒号，白名单匹配要允许无值形式。
- **E102 / W101 词表类**：见 §5.2。场景指示 `【场景：X | Y | Z】` 的三段分别对应场景 / 时间 / 镜头。
- **E103 落点不存在**：`-> x` 与 `> 选项 -> x` 的 `x` 不在标签表。
- **E104 标签重复**：同一标签名定义两次。
- **E105 控制流行缺少落点**（修订 2026-11-24）：以 `>` 开头但不满足 `^>\s*(.+?)\s*->\s*(.+)$` 的选项行；
  以及只有一个 `->`（不满足 `^->\s*(.+)$`）的跳转行。解析器把这两类整行降级成旁白，选项/跳转凭空消失。
- **W102 未知模型**：角色表第五列 `matchModel()` 返回空。
- **W103 说话人未声明**：匹配解析器的两种台词形态
  - `名字（情绪/语气）：内容` → `^([^\s:：【】\[\]>]{1,8})[（(][^）)]{1,40}[)）][:：]`
  - `名字：内容` → `^([^\s:：【】\[\]>]{1,8})[:：]`
  - `旁白` 与 `标题/简介/作者` 元信息行不参与判定。
- **W104 出场人物未声明**：`【出场：a|b】` 中的名字不在角色表。
- **W105 角色表列数 ≠ 5**。
- **W106 死标签**、**W107 无场景指示**、**W108 无显式结束**。

### 5.5 词表一致性测试（防漂移）

`tests/lint.test.mjs` 中：

1. 对 `SCENES`/`TIMES`/`CAMS`/`POSES`/`ACTS`/`VIEWS` 的**每一个 label 与 alias**，断言工具的匹配器都认得它（返回非「未知」）。
2. 对一批**故意不认识**的字符串（`未识别的场景`、`超特写`…），断言工具判为未知。
3. 断言工具对内置 15 章产出的**词表类 issue 数量为 0**。

这三条合起来保证工具的「认识 / 不认识」判定与解析器一致。

### 5.6 解析器交叉验证（兜底）

`lintText()` 内部对同一段文本调用一次 `parseScriptText(text, fileName)`：

- 成功 → 忽略（扫描器已经全量分析过）。
- 抛错 → 记一条 error，message 用解析器原文（例如「第 12 行：未识别的场景「XX」」），code 记 `E100`（解析器拒绝）；若该行已由扫描器报过 issue，则不重复报。

这样即便工具某条判定写漏了，致命错误仍然会被拦下。

## 6. CLI 契约

```
node tools/lint.js <文件...>      校验若干个 .txt / .md 剧本
node tools/lint.js --builtin      校验内置 15 章
node tools/lint.js --builtin --json
node tools/lint.js <文件> --strict   把 warning 也算作失败
```

输出示例：

```
坏剧本.txt
  第 12 行  E101 未知舞台指示标签「特写」。本项目只认：场景/分镜、镜头、姿态/情绪、动作、视角/机位、出场/登场、清场/空场/无人、结束/完
  第 34 行  E105 选项行缺少落点。正确写法：> 追问磁带 -> 追问分支
  第 51 行  W103 说话人「夏目悠真」未在角色表中声明

共 1 个错误，1 个警告（1 个文件）
```

退出码：

| 码 | 含义 |
| --- | --- |
| 0 | 通过（无 error；`--strict` 下额外要求无 warning） |
| 1 | 有 error |
| 2 | 用法错误（未知参数、文件不存在） |

`--json` 输出机器可读结果，便于将来被 P0-4 的导入前置或 CI 调用：

```json
{ "ok": false, "issues": [ { "file": "x.txt", "line": 12, "severity": "error", "code": "E101", "message": "…", "hint": "…" } ], "summary": { "errors": 1, "warnings": 1 } }
```

## 7. 测试策略

`tests/lint.test.mjs`（Node 内置测试运行器，零依赖）：

1. **规则覆盖**：每条规则（E101–E108、W101–W108）一个用例，断言 issue 的 `code`、`line`、`severity`。
2. **写坏样本**：`tests/fixtures/lint/` 放几个小样本（未知场景、断跳转、死标签、错模型名、漏选项落点、重复标签、回跳），断言 lint 能报出预期**行号与原因**。
3. **干净样本**：一个合法小剧本，断言零 issue。
4. **词表一致性**：§5.5 的三条断言。
5. **内置回归**：`lintBuiltin()` 对内置 15 章断言 **零 issue**（同时作为「工具没有误伤真实语料」的哨兵）。
6. **运行时零影响**：断言 `scripts/` 目录不引用 `tools/lint.js`（防止把离线工具拖进线上依赖图）。

运行方式：仓库根目录 `node --test`（注意：`node --test tests/` 在本仓库是坏的，不要用）。

## 8. 与既有约束的关系

| 约束 | 关系 |
| --- | --- |
| 零依赖 / 无构建步骤 | ✅ 只用 Node 内置模块 + 仓库已有模块 |
| 不加根 `package.json` | ✅ 不加 |
| **不破坏剧本解析** | ✅ `scripts/parser.js` 零改动；工具只读调用 `parseScriptText` |

| 旧存档 `mumu.saves.v1` 可读 | ✅ 本次不涉及存档结构 |
| 用户可见报错中文 | ✅ lint 全部文案中文；解析器交叉验证直接引用其中文原文 |
| 内置 15 章可播 | ✅ 由 `lintBuiltin()` 零 issue + `node --test` 全绿保证（解析器未改，播放行为不受影响） |
| 部署到 Qoder Sites | ✅ `tools/` 不参与线上运行（不被 `index.html` / `scripts/` 引用），不增加线上体积 |

## 9. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 工具的词表判定与解析器漂移 | 误报 / 漏报 | 词表一致性测试（§5.5）+ 内置 15 章零 issue + 解析器交叉验证兜底（§5.6） |
| 工具的控制流模型与解析器不一致 | 可达性结论错误 | 建图语义逐条对齐解析器的节点入队顺序（选项组延迟 push、五类指示不 flush、跳转不回落到下一行），并在 §5.3 写明对照关系 |
| 行号在「标签行」「选项行」等非节点行上失真 | 报告指向错误位置 | 标签记录定义行；选项组记录每项行号；报告里选项问题指向**具体选项行**而不是组首行 |
| `tools/lint.js` 被误当作运行时依赖 | 线上体积与耦合 | `scripts/` 不得引用它（测试第 6 条守住）；README 明确它是离线工具 |
| warning 淹没 error | 作者体验差 | 默认退出码只看 error；`--strict` 才把 warning 计入失败；内置 15 章当前 warning 为 0，说明噪声可控 |
