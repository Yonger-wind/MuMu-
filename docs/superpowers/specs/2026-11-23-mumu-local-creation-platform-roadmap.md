## 1. 产品定位与四条原则

暮幕是一个**本地优先的互动叙事创作与放映工具**：用户的作品被拥有、被演出、被分享、被再创作。

1. **作品即文件。** 平台的第一公民是用户手里的作品包（`.mumu`），不是账号，不是云端数据库。导出、备份、转发、二创都不受平台限制。
2. **本地优先。** 核心功能在无网络、无账号环境下完整可用；任何联网能力（AI 辅助、精选索引、在线分享）必须是可选项。
3. **作者演出优先。** 分镜、站位、光影、道具连续性是暮幕的护城河；不要用通用数值 HUD 破坏文学质感。关系用站位和光表达，后果用道具和台词表达。
4. **可复现与可验证。** 解析、播放、存档、导出全部确定性；AI 只做格式转换助手，不做运行时依赖。

产品北极星：**让一个用户把一段文字，在暮幕里变成一部能演、能存、能分享、能再创作的作品。**

---

## 2. 优先级判定规则

按以下四条规则排序，冲突时上位规则优先：

1. **地基优先。** 状态层、作品包格式、校验器、扩展点契约没定，任何上层功能都会返工。
2. **创作闭环优先。** 导入 → 预览 → 修正 → 发布 这条链先跑通，平台定位才成立。
3. **可玩性内核优先于装饰。** 结局、选择后果、图鉴是“可玩”的骨架；夜幕与图鉴卡是可见的糖，两者都要，但顺序不同。
4. **高风险后置。** 可视化编辑器、自由手绘画板、在线论坛（需要后端）排在最后，且可以独立立项。

## 6. 延后与明确不做

| 项 | 决定 | 原因 |
|---|---|---|
| 服务端 API 导入 | 不做（AI 走“提示词 + JSON 回贴”可选路径） | 破坏本地优先、隐私与确定性；智能性只占导入体验的一小部分 |
| 账号 / 云同步 / 在线账号体系 | 不做 | 与“作品即文件、用户拥有”冲突 |
| 自由手绘为主的人物画板 | 后置，图层拼装优先 | 自由手绘成本高、成品质量不可控 |
| 像素级自定义场景绘制 | 后置 | 27 个手绘场景是质量资产；先做“选内置场景 + 分镜编排” |
| 评论 / 排行榜 / 社交关系 | 暂不做 | 需要后端与审核；先做作品包、策展、二创 |
| AI 续写 / 润色 / 生成图片 | 不做 | 保持作者创作主线；不引入生成内容混入作品 |
| 整体 UI 重构 | 不做 | 违反项目红线；UI 以增量接入方式升级 |

## 7. 不可违反的约束（继承 AGENTS.md）

- 不引入第三方依赖、不加构建步骤、不整体重构 UI 与页面布局。
- 人物只来自立绘素材，不恢复旧剪影/卡通人物系统；不按姓名推断外观。
- 不破坏：剧本解析、人物识别、对话播放、分支、存档、角色外观稳定性、分镜系统。
- 存档兼容：`mumu.saves.v1` 旧档必须可读，新字段给默认值。
- 解析器/引擎向后兼容：旧剧本（无舞台指示、4 列角色行）照常播放。
- 视觉调整必须截图对比验收：不卡通、不贴纸、融入环境光、情绪可读、不遮挡对话框。

## 8. 执行流程与回归矩阵

每次改动必须走完以下闭环，缺一不可：

1. 改前读 `AGENTS.md` 与本计划表，确认归属阶段与依赖已满足。
2. 实现 → 自测（`node serve.js`）→ 强制刷新（`serve.js` 不发缓存头）。
3. 回归矩阵：
   - 入口：首页 → 选择剧本 → 四张曲目卡 → 章节列表 → 开演。
   - 四部曲全部 15 章至少各跑一遍关键路径与全部分支。
   - 存档：保存 → 刷新 → 读档续演位置正确；旧档可读。
   - 导入：内置剧本与自造脚本各导一次，非法脚本有明确报错。
   - 弹窗：剧本库 / 存档 / 导入 / 玩法。
   - 控制台无错误、无 404。
4. 视觉改动必须截图对比。
5. 提交信息写清阶段编号（如 `feat(P2-2): 选择写入 flag 与条件台词`）。
6. 勾选本表对应行的完成定义；未达定义不勾。
